# Neovim Operation Advisor

ユーザーが `/nvim-advisor` を実行したとき、またはNeovimの操作アドバイスを求めたときに実行するスキル。

## 処理フロー

### 1. ログファイルの読み込み

`~/.local/state/nvim/oplog.log` を読み込む。
ファイルフォーマット（TSV）:
```
UNIX_TIMESTAMP<TAB>MODE<TAB>KEYS<TAB>FILENAME<TAB>FILETYPE
```

MODE: `n`=ノーマル, `v`=ビジュアル, `i`=インサート, `c`=コマンドライン

ファイルが存在しない場合は「ログが記録されていません。nvimを使用してからもう一度実行してください。」と伝えて終了する。

### 2. パターン分析

以下の観点でログを解析する:

**非効率なナビゲーション**
- 矢印キー（`^[[A`, `^[[B`, `^[[C`, `^[[D`）を使っているか
- `hjkl` を1文字ずつ多用して単語・行単位移動（`w`, `b`, `e`, `0`, `$`, `gg`, `G`）を使っていないか
- `j`/`k` を連続して5回以上入力しているシーケンス

**繰り返しコマンドシーケンス**
- 同じキーシーケンスが3回以上出現するパターンを抽出
- コマンドラインで同じコマンドを繰り返している（`:w`, `:q`, `:wq` など）

**マクロ・dotリピートの活用機会**
- 直前と同じ操作シーケンスが連続する場合 → `.` コマンドの提案

**インサートモード操作**
- `<Esc>` → `i` の繰り返しが多い場合 → `a`, `A`, `o`, `O`, `c` 系コマンドの提案
- `<BS>` を多用している場合 → `ciw`, `ct{char}`, `s` の提案

**検索・置換**
- `:s/` の繰り返し → `cgn` ワークフローの提案

**ファイルタイプ別パターン**
- ログからファイルタイプを特定し、対応する提案を行う

### 3. ユーザーのnvim設定の確認

`~/workspace/dotfiles/config/nvim/` 配下を確認し、ユーザーがすでに設定しているキーマップと重複しない提案を行う。

### 4. 改善提案の出力

以下の形式で、優先度の高い上位5件を出力する:

```
## Neovim操作アドバイス

### 1. [改善タイトル]

**現在のパターン:** `[観測されたキーシーケンス]`（過去N回使用）
**改善案:** `[より効率的な操作]`

Before: [具体的な操作手順]
After:  [改善後の操作手順]

:help [関連するhelpタグ]

---
```

パターンが少ない場合（100行未満）は「まだデータが少ないです。しばらく使用してから再実行してください。」と伝えた上で、観測できた範囲でアドバイスを提供する。
