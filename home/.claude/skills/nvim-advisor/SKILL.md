# Neovim Operation Advisor

ユーザーが `/nvim-advisor` を実行したとき、またはNeovimの操作アドバイスを求めたときに実行するスキル。

## 処理フロー

### 1. ログファイルの読み込み

`~/.local/state/nvim/oplog.log` を読み込む。
ファイルフォーマット（TSV、1 行 = 1 キーストローク）:
```
UNIX_TIMESTAMP<TAB>MODE<TAB>KEY<TAB>FILENAME<TAB>FILETYPE
```

MODE: `n`=ノーマル, `v`=ビジュアル, `i`=インサート, `c`=コマンドライン

`KEY` の記録形式（重要）:
- 通常の ASCII キーはそのまま（`j`, `w`, `0` 等）
- 制御文字は `^M` (Enter), `^[` (Esc), `^G` 等のキャレット表記
- 特殊キーは Neovim 内部表現（K_SPECIAL バイト列 `<80>...`）で記録される。**`^[[A` のような端末エスケープシーケンスではない**
  - 矢印キー: `<80>ku`=↑, `<80>kd`=↓, `<80>kl`=←, `<80>kr`=→
  - `<80><fd>...` はプラグインイベント等の内部擬似キー（ユーザ入力ではない。**集計・計数から完全に除外**し、シーケンス分割のキーとしても扱わない — 「存在しなかった行」として読み飛ばす）

ファイルが存在しない場合は「ログが記録されていません。nvimを使用してからもう一度実行してください。」と伝えて終了する。

### 2. パターン分析

**キーシーケンス集計規則**:
- ログは 1 行 1 キーのため、「シーケンス」は **隣接行のグルーピング** で作る
- **同一 MODE かつ同一 FILENAME** が連続する範囲を 1 シーケンスとみなす（モード境界・ファイル境界で必ず分割）
- FILENAME には `minifiles://...`, `oil://...` 等の仮想バッファ名も含まれる。これらも通常ファイルと同様に FILENAME 値の一致・不一致で境界判定する
- `<80><fd>...` で始まる内部擬似キーはシーケンスから除外（ユーザ入力ではない）
- 「連続 N 回」「N 回以上出現」のカウントは上記単位で行う

**集計除外ルール**（以下はノイズ扱いとして提案対象から外す）:
- **インサートモード (`i`) の通常入力連続**: 文字入力や `^M`(Enter) の連打は執筆行為のため非効率扱いしない。インサートモードは `<BS>` 多用、`<Esc>`↔`i` 往復、補完コマンド (`^N`, `^P`, `^X`) の多用など**編集効率に関わる兆候のみ**を対象にする
- **プラグイン内部の定型シーケンス**: 仮想バッファ (`minifiles://...`, `oil://...` など) 内で同じ定型キー列が繰り返される場合はプラグイン操作の一部とみなしノイズ扱い（例: `minifiles` 内の `1000zh`）
- **mapping 展開**: ログは mapping 展開後のキー列を記録している。ユーザが実際に何を押したかは区別不能なので、**記録されたキー列をそのままユーザ操作とみなす**（例: `gj` と記録されていれば `g`+`j` の 2 キー入力として扱う）

以下の観点でログを解析する:

**非効率なナビゲーション**
- 矢印キー（`<80>ku`=↑, `<80>kd`=↓, `<80>kl`=←, `<80>kr`=→）を使っているか
- `hjkl` を1文字ずつ多用して単語・行単位移動（`w`, `b`, `e`, `0`, `$`, `gg`, `G`）を使っていないか
- `j`/`k`、および表示行移動の `gj`/`gk` を連続して5回以上入力しているシーケンス（上記「キーシーケンス集計規則」に従う）

**繰り返しコマンドシーケンス**
- 同じキーシーケンスが3回以上出現するパターンを抽出
- コマンドラインで同じコマンドを繰り返している（`:w`, `:q`, `:wq` など）

**マクロ・dotリピートの活用機会**
- 直前と同じ操作シーケンスが連続する場合 → `.` コマンドの提案

**インサートモード操作**
- `<Esc>` → `i` の繰り返しが多い場合 → `a`, `A`, `o`, `O`, `c` 系コマンドの提案
- `<BS>` を多用している場合 → `ciw`, `ct{char}`, `s` の提案

**検索・置換**
- `:s/` の繰り返し → `cgn` ワークフローの提案

**ファイルタイプ別パターン**
- ログからファイルタイプを特定し、対応する提案を行う

### 3. ユーザーのnvim設定の確認

`~/workspace/dotfiles/config/nvim/` 配下を確認し、ユーザーがすでに設定しているキーマップと重複しない提案を行う。

### 4. 改善提案の出力

**優先度の決定基準**（降順で大きいほど優先）:
1. 発生回数（当該非効率パターンが観測された総回数）
2. 代替手段の未採用度（提案する効率コマンドが直近ログに 0〜わずかしか現れない場合を高く）
3. 日常影響度（総入力回数に占めるモード割合を目安に、主要モードに関わるものほど高く評価）

スコアは厳密な数値計算ではなく**定性評価で可**。簡易ルール: (a) 発生回数が桁違いに多いものを先頭、(b) 同桁内では代替手段の使用回数が少ない提案を優先、(c) なお並び順が決まらない場合は日常影響度（ノーマル/インサート/コマンドの利用頻度）で決める。**同点の場合は「発生回数」が多い方を優先**。上位 5 件を出力する。

出力形式:

```
## Neovim操作アドバイス

### 1. [改善タイトル]

**現在のパターン:** `[観測されたキーシーケンス]`（過去N回使用）
**改善案:** `[より効率的な操作]`

Before: [具体的な操作手順]
After:  [改善後の操作手順]

:help [関連するhelpタグ]

---
```

**データ量が少ない場合の分岐**:
- 判定対象は **全行数**（モード別ではなく、ログファイル全行のカウント）
- 100 行未満: 「まだデータが少ないです。しばらく使用してから再実行してください。」を冒頭に出した上で、観測できた範囲で **1 〜 3 件** のアドバイスを提供する（最低 1 件、最大 3 件、5 件制約を緩める）。該当パターンが皆無なら「現時点では特筆すべき非効率は観測できませんでした」と 1 行だけ添える
- 100 行未満時は「過去 N 回使用」のような定量表現を避け、「連続入力」「連打」等の定性表現に置き換える
- 出力テンプレの `（過去N回使用）` 部分は `（観測された範囲）` に置換する（完全省略ではなく明示的に置換）
