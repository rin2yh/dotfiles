# 日本語文章のルール

LLM が書いた文章は、内容ではなく体裁で「ちゃんと書いている感」を出そうとする癖がある。
以下は書く前に守るもので、`home/textlint/` の辞書は書いた後に取りこぼしを拾う網でしかない。

## 削除テスト

語を消して命題が変わらないなら、その語は要らない。

- 程度副詞（`非常に`、`極めて`、`しっかりと`、`まさに`）は根拠を示さない。消す
- `重要`、`不可欠`、`鍵となる` は、満たせなかったとき何が起きるかで示す
- `様々な`、`多角的に` は範囲を述べたように見えて何も限定していない。数を書くか列挙する
- `掘り下げる`、`紐解く` は動作を指していない。実際にする操作の名前を書く

## 書かないもの

- 予告（`本記事では〜を解説します`）と要約（`まとめると`）。目次と見出しで足りる
- 締めの常套句（`〜の第一歩となるでしょう`、`いかがでしたでしょうか`）
- 絵文字。見出しと本文のどちらでも情報を足さない
- em dash。日本語では読点か括弧で書ける

## 断定と留保

根拠があるなら断定する。`〜と言えるだろう` は検証を省いた印になりやすい。

一方で、**本当に不確実なことは不確実だと書く**。`かもしれない` を避けるために
根拠のない断定に置き換えるのは、AI っぽさを消すどころか文章を悪くする。
消すべきなのは逃げのヘッジであって、正直な留保ではない。

## 確認

書き終えたら実行する。`Warning` は書き直しの方針が指摘文に入っている。

```bash
cd ~/workspace/dotfiles/home/textlint
npm run lint          -- <file>   # Markdown の本文
npm run lint:comments -- <file>   # YAML / シェル / JS などのコメント
npm run lint:text     -- <file>   # PR 本文・コミットメッセージ
```

PR の本文とコミットメッセージは `PreToolUse` フックが投稿の直前で検査する。
指摘があれば投稿そのものが拒否されるので、手で実行するのは書きながら確かめたいときだけでよい。

この経路を足したのは、`lint:text` を用意しただけでは実際に飛ばしたため。
「書いたら検査する」を記憶に任せると必ず抜ける。止めるなら送信口に置く。
