# 規則の書き方

`SKILL.md` の「4. 規則を書く」から参照する。実際に規則を書くときだけ読めばよい。

## 基本の形

`patterns` と `specs` を必ずセットで書く。prh は `specs` が 1 件でも外れると
辞書のロード自体を失敗させるため、`specs` がそのまま回帰テストになる。
書いたつもりのパターンが実際にはマッチしていない、という一番ありがちな失敗をここで潰せる。

```yaml
  - expected: 数を書くか列挙する
    scope: chat
    patterns:
      - 様々な
      - さまざまな
    specs:
      - from: 様々な要因がある
        to: 数を書くか列挙する要因がある
```

`ai-tone-review.yml` では `expected` が本文に差し込まれた文字列が `to` になる。
日本語として不自然に見えるが、この辞書には fixer を登録していないので本文には届かない。
`specs` の役目はパターンが当たることの確認であって、出力の自然さではない。

## 外した語を見張りにする

`from` と `to` を同じにした `specs` は「この規則にマッチしないこと」の表明として使える。
判断して外した語をここに残しておけば、戻そうとした人の手元で `ai-tone check` が落ちる。
「なぜ入れなかったか」をコメントで説明するより、テストで守るほうが強い。

```yaml
    specs:
      - from: 様々な要因がある
        to: 数を書くか列挙する要因がある
      - from: 幅広い層に使われている      # 外した語。戻すとここで落ちる
        to: 幅広い層に使われている
```

## 除外文字は活用形を数えてから決める

副詞を削る規則でいちばん多い事故は、除外する文字を思いついた 1 つで済ませることにある。
「しっかりした」が頭に浮かぶと `[^し]` と書いてしまうが、同じ語は
`する` `される` `せず` `させる` でも述語を作る。除外が 1 つでも漏れると、そこから本文が壊れる。

副詞 + サ変述語の形を疑ったら、**語幹を機械的に並べる**。

| 形 | 後続 |
| --- | --- |
| した / している | し |
| する | す |
| せず / せよ | せ |
| される / させる | さ |

`しっかり感` のように名詞をつくる形も同じで、削ると「感のある作り」になる。

```yaml
  # 「しっかりした」「しっかりする」「しっかりせず」を巻き込まずに
  # 「しっかり検証する」だけを削る。除外は思いついた形ではなく活用の一覧から作る。
  - expected: $1
    pattern: /しっかり([^しすせさと感])/
```

除外を広げると `しっかり住み分ける` のような正当な指摘も少し取りこぼすが、
`--fix` が原稿を壊す損失のほうがはるかに大きい。**迷ったら取りこぼす側に倒す。**

書いたら、その語に `する` `される` `せず` `させる` を付けた文を `dict/fix-safety.txt` へ入れて
`ai-tone check` を通す。漏れがあればそこで落ちる。

## prh の正規表現の制約

踏むと辞書のロードが失敗するので先に知っておく。

- リテラルに使えるフラグは `gimy` だけ。`/.../u` と書くと正規表現として認識されず、
  文字列リテラルとして丸ごとエスケープされる
- `u` フラグが常に付与されるため、`\u{...}` とサロゲートペアが書けない。
  絵文字のような文字は実物を `patterns` に列挙する
- prh が見るのは Markdown の記法を取り除いた本文。`^#` のような記法依存の判定はできない
- 後方参照は `$1` 形式（`\1` ではない）。prh は複数の `patterns` を 1 本の選択に畳むため
  グループ番号がずれる。後方参照を使う規則は 1 パターンずつ別の規則に分ける
- **会話検査は Go の regexp（RE2）で当てるので先読みが無い。** `(?!...)` を書くと
  textlint は解釈するが会話検査の網だけが減る。除外は「後続の 1 文字を捕まえて `$1` で書き戻す」形にする

## 否定後読みの代わり

同じ語が別の意味で使われる場合、直前の語で切り分けたいことがある。
prh には否定後読みが無いので、直前を捕まえて `regexpMustEmpty` で「空のときだけ一致」とする。

```yaml
  # 要約の「まとめると」だけを拾い、「1 つにまとめると」のような条件の「〜と」は拾わない
  - expected: 要約を削るか、要約だけを残して本文を削る
    pattern: /(に|へ|と|で|を)?まとめると/
    regexpMustEmpty: $1
```
